##### 任务定义和公平条件

在静态一般有向无权原图上精确判断 $d_G(s,t)\le k$，分别评估固定 $k$ 与混合 $k$；两者使用同一原图、同一冻结查询及相同顺序，训练、验证、测试查询相互独立。每项配置必须通过全部逐条答案核验，存在错答或未完成构建的配置不参加性能排名

主对比默认单线程构建及查询、串行运行、同一 CPU 亲和性及同一内存预算。不设置墙钟超时。按图规模选择统一预算，当前普通图为 48 GiB；超限配置在独立的大图压力实验中逐级提高至 256、384、448 GiB，等待共享主机有足够可用内存后开工，准确记录实际预算。压力实验使用并行构建时单独记录线程数，构建时间只在相同资源条件下作严格比较。容量证据、分配失败、运行中等状态分别保存

##### 指标及测量口径

| 指标 | 定义及测量 |
| --- | --- |
| 构建成本 $B$（s） | 从公共原图准备完成开始，计入所有索引构建、选点、训练探测、半径分配及重建成本 |
| 查询延迟 $t$（µs/query） | 单线程，预热一轮，然后同一冻结请求完整重复五轮，取五个批次总耗时的中位数除以查询数 |
| 查询吞吐 | $10^6/t$ queries/s；另保留首个计时批次和重复次数 |
| 索引空间 $S$（bytes） | 持久辅助索引实际分配容量，包括行容器、标签、边界及查询元数据；公共原图和临时构建工作区除外 |
| 方法报告负载 | 方法原有的逻辑大小或编码流大小，保存原始定义用于论文复核 |
| 查询就绪 RSS | 索引和查询底座就绪时的进程驻留内存，来自 Linux statm，包含图及程序运行开销；共享候选进程的 RSS 单独保存 |
| 峰值 RSS | 单配置进程高水位，涵盖构建与查询阶段，GNU time 采集 |

查询计时不包含磁盘读写、建索引及独立正确性校验。批次中每条查询的布尔结果需写入答案数组，并在计时外核验各轮一致和真值一致。历史首次批次结果仍保留，严格比较使用同一计时协议。P95 只有在独立采集逐条耗时时才报告，批次均值不能推出 P95

固定阈值索引在混合阈值负载下的构建及查询总时间按各档相加，持久索引空间按各档相加，若累计索引负载已超过统一预算则记为不可行；单进程峰值和查询就绪 RSS 取各档最大值，用于描述单次独立构建，不能代表多档同时驻留的内存。原生通用阈值索引只构建一次

冻结数据提供正查询、距离超过 $k$ 的可达负查询和全局不可达负查询的类别；逐类性能试验使用同一类别组成的冻结请求，均匀点对与难度分层的负载独立运行。当前综合排名使用混合负载。两份结果的图哈希、查询哈希、配置和计时协议必须一致

##### 综合排名

设在线双向限深 BFS 的平均查询时间为 $t_0$ 秒，索引方法的平均查询时间为 $t$ 秒。预期服务 $Q$ 条与测试同分布的查询时，总时间和摊销加速比为

$$
C_Q=B+Qt,\qquad AS_Q=\frac{Qt_0}{B+Qt}=\frac{t_0}{t+B/Q}
$$

主指标暂固定为 $Q=10^6$ 的 $AS_Q$，越大越好；同时报告 $Q=10^9$ 和实际测试批次大小下的摊销加速比。对同一张图和相同查询分布，按 $AS_Q$ 降序与按 $C_Q$ 升序等价。采用预先确定的需求规模，避免为单个方法选择有利的查询量。双向 BFS 作为零索引在线参照，其 $AS_Q=1$

独立报告纯查询加速 $t_0/t$、构建时间、查询延迟、辅助索引大小和峰值 RSS 的排序。若 $t<t_0$，达到相对双向 BFS 的时间成本盈亏平衡所需查询数为

$$
Q_\mathrm{break}=\left\lceil\frac{B}{t_0-t}\right\rceil
$$

其他配置记录无有限回收点。对于 $S>0$ 的索引，附加空间效率 $CP=(t_0/t)/(S/2^{20})$ 与摊销空间效率 $OG_Q=AS_Q/(S/2^{20})$，按每 MiB 表示，用于辅助判断每单位空间的收益

跨图总体比较使用全部入选方法都已验收的共同图集，对逐图 $AS_Q$ 和纯查询加速取几何平均；同时列出各方法完整图数与共同图名称，避免高难度缺测影响排序。大图压力数据根据资源组分别报告。无索引及少量索引方案使用同样的总耗时指标，索引大小为零时空间效率未定义
